# Task 2: API Specification — Elevator Fleet Service

---

## 1. Outcomes

The Elevator Fleet Service is a Go HTTP API that exposes Ontario elevator fleet data as structured JSON. It serves two consuming clients: the existing HTMX/Flask dashboard (desktop browser) and future mobile clients. Both clients need a single, typed, cacheable source of fleet truth rather than reading CSVs directly or calling Flask HTML endpoints.

**Done looks like:**

- `GET /api/elevators` returns a paginated fleet list; every elevator in `merged_elevator_data.csv` is reachable.
- `GET /api/elevators/{id}` returns full static detail for any known elevator ID with all fields typed correctly.
- `GET /api/elevators/{id}/inspections` returns the complete per-elevator inspection history, with each inspection's linked compliance orders nested inline.
- `GET /api/elevators/{id}/risk` returns the ML-predicted next inspection outcome and current open-order risk for any known elevator ID.
- All four endpoints return `Content-Type: application/json`.
- Unknown IDs return `404` with a structured JSON error body.
- Malformed path or query parameters return `400` with a structured JSON error body.
- A developer can build a complete fleet dashboard — fleet list, detail panel, inspection history, risk indicators — from these four endpoints alone.

---

## 2. Scope Boundaries

### In scope

- `GET /api/elevators` — paginated fleet list
- `GET /api/elevators/{id}` — per-elevator static detail
- `GET /api/elevators/{id}/inspections` — full inspection history from `inspection.csv`, with linked compliance orders from `order.csv`
- `GET /api/elevators/{id}/risk` — ML-predicted outcome from `predictions.csv` plus current open-order risk indicators from `order.csv`
- JSON-only responses (`Content-Type: application/json`) for all four endpoints
- Read-only access to CSV files loaded at startup

### Out of scope

- **Write operations** — no POST, PUT, PATCH, or DELETE endpoints
- **Authentication / authorisation** — no auth headers, tokens, or role checks
- **HTML rendering** — this service returns data only; HTML remains the Flask/HTMX layer's responsibility
- **Pagination on sub-resources** — `/inspections` and `/risk` are not paginated. Per-elevator inspection counts are bounded (the dataset has 143,181 inspections across 43,251 elevators; median is ~3 per elevator). Returning the full list per request is acceptable.
- **Pagination on the fleet list** — included. The fleet is 43,251 rows; returning the full set in one response is impractical for mobile clients and unnecessary for dashboard use.
- **Compliance orders as a top-level resource** — order data surfaces through `/risk` (open-order count, mean risk score) and nested inside `/inspections` (per-inspection orders). A standalone `/api/elevators/{id}/orders` endpoint is not included.
- **Caching headers, ETags, rate limiting** — deferred to a later task

---

## 3. Constraints & Assumptions

- **Language:** Go
- **Data sources:** local CSV files — `data/merged_elevator_data.csv`, `data/inspection.csv`, `data/order.csv`, `data/predictions.csv`
- **Load strategy:** all CSVs are read into memory at startup; no database
- **Read-only:** no mutations to any CSV file at runtime
- **Content type:** all responses are `application/json`; the `Content-Type` response header is always `application/json; charset=utf-8`
- **Date normalisation:** CSV files store dates in three inconsistent formats (`28-Apr-17`, `1/10/2011`, `2015-03-27`). The service normalises all dates to ISO 8601 (`YYYY-MM-DD`) before writing them to JSON. Timestamps in `order.csv` (`DateofIssue`: `3/5/2012 14:08`) are truncated to date only.
- **Boolean coercion:** `under review` in `merged_elevator_data.csv` stores `"Y"` or `"N"`. The API exposes this as a JSON boolean (`true` / `false`).
- **Null coercion:** `alteration_count`, `latest_alteration_type`, and `latest_alteration_status` are NaN in `merged_elevator_data.csv` for elevators with no alteration history. The API exposes these as JSON `null`.
- **Redacted fields omitted:** `LICENSEHOLDERACCOUNTNUMBER`, `BILLINGACCOUNT`, and `Owner Account Number` contain the literal string `"data redacted"` or `"redacted"` in the source data. These columns are not exposed in any API response.
- **`predictions.csv` forward dependency:** this file does not yet exist. It will be generated by the Task 6 ML pipeline. The `/risk` endpoint is fully specified here so its contract is agreed before implementation. If `predictions.csv` is absent at startup, or if the requested elevator ID has no prediction row, the endpoint returns `503 Service Unavailable` with `PREDICTIONS_UNAVAILABLE`.
- **`elevator_id` alias:** `platform/elevator_fleet.csv` names the key `elevator_id`; all other files use `ElevatingDevicesNumber`. These are the same values. The API exposes the field as `id` in all responses.

---

## 4. Prior Decisions

- **Pure JSON, no HTML.** This service is a data API. All HTML rendering remains the responsibility of the Flask/HTMX layer or any future frontend framework. The service never calls `render_template` or returns `text/html`.
- **REST resources modelled around elevators.** The elevator (`/api/elevators/{id}`) is the primary resource. Inspections and risk are sub-resources. This keeps URLs shallow and discoverable.
- **CSV as the data source.** No database migration is required or planned for this service. The Go service loads all source CSVs at startup and queries them in memory.
- **`ElevatingDevicesNumber` is the canonical elevator identifier.** It is an integer in every source file. The API exposes it as `id` (JSON number). String-format IDs are not supported.
- **`InspectionNumber` / `inspectionnumber` is the join key between `inspection.csv` and `order.csv`.** The `/inspections` endpoint uses this key to nest orders inside each inspection record.
- **Compliance orders are not a top-level resource.** Order data appears in two places: nested under inspections (full detail, via `/inspections`) and summarised at the elevator level (open-order count + mean risk score, via `/risk`). This covers the dashboard's needs without adding a fifth endpoint.
- **`Device Class` is always `"Elevators"` in this dataset.** It is included in the `/api/elevators/{id}` response for completeness but adds no filtering value.

### 5.4 `GET /api/elevators/{id}/risk`

**Method:** `GET`  
**Path:** `/api/elevators/{id}/risk`  
**Description:** Returns the ML-predicted next inspection outcome and current compliance risk indicators for a single elevator.

**Forward dependency:** This endpoint reads from `data/predictions.csv`, which does not yet exist. It will be generated by the Task 6 ML pipeline (Random Forest classifier trained on `data/feature_matrix.csv`). The response shape is fully defined here so the endpoint can be implemented and stubbed before Task 6 completes. At runtime, if `predictions.csv` has not been loaded or the elevator has no prediction row, the endpoint returns `503 Service Unavailable`.

**Expected `predictions.csv` schema** (to be confirmed in Task 6):

| Column | Type | Description |
|--------|------|-------------|
| `ElevatingDevicesNumber` | int | Join key |
| `predicted_outcome` | string | Highest-probability outcome class (one of the 13 `outcome_class` values from `feature_matrix.csv`) |
| `confidence` | float | Probability of the predicted class (0.0 – 1.0) |
| `prob_all_orders_resolved` | float | Class probability |
| `prob_complete` | float | Class probability |
| `prob_dc_follow_up` | float | Class probability |
| `prob_fail_initial` | float | Class probability |
| `prob_follow_up` | float | Class probability |
| `prob_follow_up_initial` | float | Class probability |
| `prob_follow_up_major` | float | Class probability |
| `prob_follow_up_sub_major` | float | Class probability |
| `prob_other` | float | Class probability |
| `prob_passed` | float | Class probability |
| `prob_passed_major` | float | Class probability |
| `prob_shutdown` | float | Class probability |
| `prob_unable_to_inspect` | float | Class probability |
| `model_version` | string | Model identifier (e.g. `random_forest_v1`) |
| `generated_at` | string | ISO 8601 date when predictions were generated |

### 5.6 `GET /api/fleet/alerts`

**Method:** `GET`
**Path:** `/api/fleet/alerts`
**Description:** Returns elevators requiring immediate attention — those with both a `high` risk level (from `predictions.csv`) and a non-passing most-recent inspection outcome (from `inspection.csv`). Results are sorted by `risk_score` descending. Returns an empty array when no elevators meet both conditions. Returns 503 when `predictions.csv` has not been loaded.

#### Query parameters

None.

#### Response — 200 OK

```json
[
  {
    "elevator_id": 27557,
    "risk_score": 0.908,
    "risk_level": "high",
    "last_inspection_date": "2014-03-05",
    "last_inspection_outcome": "Follow up",
    "equipment_type": "Passenger Elevator"
  },
  {
    "elevator_id": 27558,
    "risk_score": 0.8684,
    "risk_level": "high",
    "last_inspection_date": "2014-03-05",
    "last_inspection_outcome": "Follow up",
    "equipment_type": "Passenger Elevator"
  }
]
```

Returns `[]` (empty JSON array) when no elevators meet both conditions.

#### Response field types

| Field | JSON type | Source column | Source file |
|-------|-----------|---------------|-------------|
| `elevator_id` | number (int) | `ElevatingDevicesNumber` | `merged_elevator_data.csv` |
| `risk_score` | number (float) | `risk_score` | `predictions.csv` |
| `risk_level` | string | `risk_level` | `predictions.csv` |
| `last_inspection_date` | string (ISO 8601 date) or null | `Latest_INSPECTION_Date` | `inspection.csv` |
| `last_inspection_outcome` | string | `InspectionOutcome` | `inspection.csv` |
| `equipment_type` | string | `Device Type` | `merged_elevator_data.csv` |

**Alert criteria:** An elevator appears in this response when ALL of the following are true:
1. Its `risk_level` in `predictions.csv` is `"high"`.
2. Its most-recent inspection outcome (the row with the lexicographically greatest `Latest_INSPECTION_Date`) is NOT one of the pass outcomes: `Passed`, `Passed Major`, `Passed Sub`, `Complete`, `Complete Enforcement`, `All Orders Resolved`.

Elevators with no inspection record, or with no prediction row, are excluded.

**Sort order:** Descending by `risk_score`.

#### Error responses

| HTTP status | `error` code | Condition |
|-------------|--------------|-----------|
| `503` | `PREDICTIONS_UNAVAILABLE` | `predictions.csv` not loaded |

```json

  "error": "PREDICTIONS_UNAVAILABLE",
  "message": "predictions are not yet available"
}
```
